## 使用

### 1. 初期設定 (`config.json`)
システムを初めて起動する前に、 `config.json` という名前のファイルを作成する必要があります。システムはこのファイルに基づいて物理ドライブとファイルパスを特定します。

* **`base_dirs`**: メディアライブラリが存在するルートディレクトリのリスト（複数のハードドライブ/パスの組み合わせをサポート）。
* **`system_data_dir`**: システムのタグ、統計、キャッシュなどのデータ保存場所（デフォルトの `./data` で構いません）。
* **`modes`**: システムがサポートする「モード」。各モードには ID（例: `MUSIC`）、表示名 `name`、およびそのモードに対応する本体フォルダ名 `pages` と カバーフォルダ名 `cover` が含まれます。
* **`extensions`**: （オプション）システムが認識するファイル拡張子のタイプをカスタマイズします。

---

### 2. 検索機能
検索ボックスにキーワードを入力し、Enterキーを押すか、「検索」ボタンをクリックします。システムは、ファイル名またはタグ名にキーワードが含まれるアイテムを自動的にマッチングします。

* **⚡キャッシュの高速化**：「秒速検索」を体験するために、新しいファイルを追加した後は、まず右上の `管理 -> キャッシュ更新` をクリックすることを強くお勧めします。システムがバックグラウンドで高速インデックスを構築し、その後の検索が一瞬で完了するようになります。

---

### 3. タグ絞り込み機能
任意のタグを直接クリックすると、それがフィルター条件として適用され、選択されたタグは**赤色**にハイライトされます。もう一度クリックすると選択が解除されます。
* **複数タグの組み合わせ**：複数のタグを同時にクリックできます。
* **展開/折りたたみ**：タグの数が多すぎて画面を遮る場合は、タグバーの右端にある `v` ボタンをクリックして、タグパネルを折りたたんだり展開したりできます。

### 4. 右上「管理」メニュー機能
UI右上にある **管理 (Maintenance)** ボタンには、システムのメンテナンスおよびデータ管理ツールが含まれています。クリックして展開すると、各機能キーの役割は以下の通りです：

#### 🔄 キャッシュ更新
* **役割**：現在のモード（MUSIC、GAMEなど）でマウントされているすべてのハードドライブ内のファイルディレクトリを強制的に再スキャンし、構造キャッシュ（`[MODE]_cache.json`）を再生成します。
* **利用シーン**：システムの外部（Windowsエクスプローラーなど）でファイルを追加、削除、または移動した後にこのボタンをクリックすると、システムが即座に最新の状態と同期され、高速な検索とブラウジング機能の正確性が確保されます。

#### 🧹 無効記録の破棄
* **役割**：システムの設定ファイル（`tags.json` および `stats.json`）をディープスキャンし、**物理ファイルがすでに存在しない**タグ記録やアクセス統計を自動的に検出して削除します。
* **利用シーン**：長期使用後、大量の古いファイルを削除した場合、これらのファイルに残されたタグや統計データがスペースを占有し、エラーを引き起こす可能性があります。定期的にこのボタンをクリックしてデータベースをクリーンに保ちます。操作前にシステムは自動的にバックアップファイル（日付サフィックス付き）を作成します。

#### 📄 構造エクスポート
* **役割**：現在すべてのモードとメディアライブラリのファイルツリー構造をプレーンテキストのリストとしてエクスポートします。
* **利用シーン**：メディアライブラリのディレクトリをバックアップするため、またはコレクションリストとして共有するために使用します。エクスポートされたファイル名は `library_structure.txt` で、`data/` ディレクトリに保存されます。

#### 🏷️ タグ編集
* **役割**：クリックするとグローバルな「タグ編集モード」に入ります（ボタンが赤くなり警告します）。このモードでは：
    1. カード上のファイル名をダブルクリックして直接**名前の変更**ができます（システムは対応するファイルの物理名および関連するタグの関連付けを自動的に同期して変更します）。
    2. タグ上の `x` をクリックするとタグを削除できます。
    3. `+` をクリックすると現在の作品に新しいタグを追加できます。
* **保存**：編集が完了した後、赤くなった **タグを保存** ボタンを再度クリックすると、すべての変更が正式にサーバーの `tags.json` に書き込まれます。

## アピールポイント

### 🌟スクロールとジャンプの完璧な画像閲覧体験

画像ビューア（Image Viewer）の設計において、 **「シームレスな縦スクロール」** と **「プログレスバーによる正確なジャンプ」** を深く融合させました。

**1. パフォーマンスと進捗の同期 `IntersectionObserver` 駆動**
* **ロジック**：二重の `IntersectionObserver` を導入しました。
    * `preloadObserver` は、視界に入る前の画像を事前に読み込みます（シームレスなスクロールを実現）。
    * `readObserver` は、現在視界の正確な中央にある画像がどれかを判定し、その状態をリアルタイムで右側の「プログレスバー」にフィードバックします。

**2. コア技術：視覚的中心の維持とスクロール補償（`setGlobalZoom`）**
* **課題**：縦長スクロールでの閲覧中、ユーザーが画像を拡大/縮小すると、コンテナのコンテンツ高さが瞬時に変化するため、現在見ている画面が急に画面外へ「飛んでしまう」ことがよくあります。
* **解決策**：`ui.js` の `setGlobalZoom` 関数内で、**「相対的視覚中心のオフセット補償」**アルゴリズムを実装しました。
    * ズームがトリガーされる前に、まず現在のターゲット画像が視界の中央でどの割合の位置にあるかを計算します：`relativeCenterY = (viewCenterY - imgRect.top) / imgRect.height`。
    * CSSカスタムプロパティ `--global-zoom` を使用して全体を無劣化で拡大します。
    * ズーム完了後、**直ちに高さの差を計算し、`container.scrollTop` を手動で補償（調整）します**。これにより、先ほどの `relativeCenterY` のアンカーポイントを強制的に画面の真正面（中央）に引き戻します。

---

### 📊 熱量密度を備えたスマート統計システム

**1. アクセスカウントロジック（`backend_logic.py`）**
* **統計ロジック**：バックエンドの `update_view_count` 関数では、階層化された統計戦略を採用しています。「ディレクトリの総クリック数（total_views）」と「内部サブページのクリック数（pages/files）」に分けています。
* **連続操作の防止（デバウンス）**：ユーザーの頻繁な出入りによってデータが水増しされるのを防ぐため、`SESSION_TIMEOUT = 60` を導入しました。システムは `last_accessed` のタイムスタンプを記録し、前回のアクセスから60秒以上経過している場合のみ、メインディレクトリの閲覧数を +1 します。ただし、内部のページ（Identifier）の閲覧については、1ページごとのアクセスを正確に記録します。

**2. 情報密度が極めて高い「マイクロヒストグラム」UI（`ui.js` / `style.css`）**
* **UIの特色**：統計リスト（Stats View）において、重いサードパーティのグラフライブラリは使用せず、コンパクトなヒストグラム（`compact-histogram`）を自作しました。
* **レンダリングロジック**：
    * フロントエンドの `renderHistogram` は、ある作品のすべてのサブページ（漫画の各ページなど）のアクセスデータを読み込みます。
    * 最もアクセス数の多いページを基準 `maxItemViews` として見つけ出します。
    * 純粋なCSSを使用して高さのバーを動的に生成します：`height: ${(node.views / maxItemViews) * 100}%`。
* **ユーザー体験**：
    * ユーザーが統計項目を開くと、下に波打つような棒グラフが即座に展開されます。棒が高い場所は、その漫画やイラスト集の中で「名シーン」を示しています。
    * **ワンクリックで直接ジャンプ**：マウスをホバーすると具体的なページ番号と回数が表示され、任意の棒をクリック（`jumpAndOpen` をトリガー）すると、システムは一瞬で統計画面を抜け、該当する作品を直接開き、その正確なページまでスクロールして位置を合わせます！

## 細かいロジック分析

#### タグ編集およびリネーム操作のロジック

本システムのタグ編集およびリネーム操作は、UIの遅延を防ぐSPA指向のトランザクション設計を採用しています。ユーザーが編集後に「保存」をクリックすると、フロントエンド（`main.js` の `api.saveBatchEdits`）が変更パッケージを一括送信します。バックエンド（`app.py` の `/api/batch_edit`）はこれを受け取り、①即座に同期的処理として、物理ディスク上のファイル名変更（`os.rename`）、`tags.json` のディスクとメモリへの上書き保存（`logic.save_tags` および all_tags の更新）、そして古い `_cache.json` のディスクおよびメモリ（`GLOBAL_JSON_CACHE`）からの即時削除を行い、直ちにフロントエンドへ完了を通知して画面のリロードなしで操作を継続させます。その後、②非同期処理として、裏側でスレッドロック付きのバックグラウンドスレッド（`threading.Thread`）が起動し、全ディスクスキャンによる新しい `_cache.json` の再構築（`logic.build_and_save_cache`）を数秒かけて静かに実行します。再構築の完了後、ユーザーが新たにブラウズや検索を行った際に、③遅延読み込み（`Lazy Loading`）として `get_mode_cache` 関数が新しいキャッシュファイルを検知してメモリへロードし、システムは自動的にミリ秒単位の高速レスポンスへ復帰する仕組みとなっています。
