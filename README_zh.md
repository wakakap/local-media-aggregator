## 使用

### 1. 初始配置 (`config.json`)
在首次启动系统前，你需要在项目根目录（`app.py` 同级目录）下创建一个名为 `config.json` 的文件。系统依赖此文件来定位你的物理硬盘和文件路径。

在该文件中，你需要配置以下核心内容：
* **`base_dirs`**: 你的媒体库所在的根目录列表（支持多硬盘/多路径组合）。
* **`system_data_dir`**: 系统的标签、统计、缓存等数据的保存位置（默认 `./data` 即可）。
* **`modes`**: 系统支持的“模式”。每个模式包含一个 ID（如 `MUSIC`），显示名称 `name`，以及该模式对应的正文文件夹名称 `pages` 和 封面文件夹名称 `cover`。
* **`extensions`**: （可选）自定义系统识别的文件扩展名类型。

---

### 2. 搜索功能的使用 (Search)
系统顶部导航栏提供了一个全局搜索框，搜索范围将限定在**当前左上角下拉菜单选中的模式**（如当前在“音乐库”，则只搜音乐）。

* **如何使用**：在搜索框中输入关键字，按下回车键（Enter）或点击“搜索”按钮。系统将自动匹配文件名或标签名中包含该关键字的项目。
* **⚡ 进阶技巧 (缓存加速)**：为了获得“秒搜”体验，强烈建议在添加新文件后，先点击右上角的 `管理 -> 更新缓存`。系统会在后台构建高速索引，之后的搜索将瞬间完成。

---

### 3. 标签筛选功能的使用 (Tag Filter)
在路径导航栏的下方，有一排可点击的标签栏，用于快速筛选当前模式下的作品。

* **选择与取消**：直接点击任意标签即可将其作为过滤条件，被选中的标签会变成**红色**高亮状态。再次点击即可取消选中。
* **多标签组合 (AND 搜索)**：你可以同时点击多个标签。系统采用的是“且 (AND)”逻辑，即只有**同时包含**所有被选中标签的作品才会被显示出来。
* **展开/收起**：如果标签数量太多遮挡了视线，可以点击标签栏最右侧的 `v` 按钮来折叠或展开标签面板。

## ⚙️ 右上角“管理”菜单功能说明
UI 右上角的 **管理 (Maintenance)** 按钮包含了一系列系统维护和数据管理工具。点击展开后，各功能键的作用如下：

### 🔄 更新缓存 (キャッシュ更新)
* **作用**：强制系统重新扫描当前模式（如 MUSIC, GAME 等）下所有挂载硬盘中的文件目录，并重新生成结构缓存（`[MODE]_cache.json`）。
* **使用场景**：当你在系统外部（如通过 Windows 资源管理器）添加、删除或移动了文件后，点击此按钮可让系统立即同步最新状态，确保极速搜索和浏览功能的准确性。

### 🧹 清理无效数据 (無効記録の破棄)
* **作用**：深度扫描系统的配置文件（`tags.json` 和 `stats.json`），自动检测并剔除那些**物理文件已经不存在**的标签记录和访问统计。
* **使用场景**：长期使用后，如果你删除了大量旧文件，这些文件残留的标签和统计数据会占用空间并可能导致异常。定期点击此按钮可保持数据库干净，操作前系统会自动创建备份文件（带日期后缀）。

### 📄 导出目录结构 (構造エクスポート)
* **作用**：将当前所有模式和媒体库的文件树状结构，导出一份纯文本清单。
* **使用场景**：用于备份你的媒体库目录，或者作为藏品清单分享。导出的文件名为 `library_structure.txt`，保存在你的 `data/` 目录中。

### 🏷️ 编辑标签 (タグ編集)
* **作用**：点击后全局进入“标签编辑模式”（按钮会变红提示）。在此模式下：
    1. 你可以直接双击卡片上的文件名进行**重命名**（系统会自动同步修改对应文件的物理名称及相关标签关联）。
    2. 点击标签上的 `x` 可以删除标签。
    3. 点击 `+` 可以为当前作品添加新标签。
* **保存**：编辑完成后，再次点击变红的 **保存标签 (タグを保存)** 按钮，所有更改才会正式写入服务器的 `tags.json` 中。

### 🌟 丝滑的滚动与完美的跳转

**1. 性能与进度同步 (`IntersectionObserver` 驱动)**
* **实现逻辑**：没有使用低效的 `onscroll` 事件监听，而是引入了双重 `IntersectionObserver`。
    * `preloadObserver` 负责预加载即将进入视口的图片（实现无缝滚动）。
    * `readObserver` 负责精准判定当前视口中央是哪一张图片，并实时将状态反向同步给右侧的“进度条 (Progress Bar)”。
* **体验**：用户可以随心所欲地猛烈滚动鼠标滚轮，侧边进度条会如影随形地实时高亮当前位置；反之，点击进度条任意位置，也能平滑跳转到对应图片，两者状态永远保持完美一致。

**2. 核心技术：视野中心防抖与补偿 (`setGlobalZoom`)**
* **痛点**：在长图滚动浏览中，如果用户放大/缩小图片，由于容器内容高度瞬间突变，极易导致当前正在看的画面瞬间“飞”出屏幕（视野乱蹦）。
* **解决方案**：在 `ui.js` 的 `setGlobalZoom` 函数中，我实现了一套**“相对视心偏移补偿”**算法。
    * 在触发缩放前，先计算当前阅读目标图片所在的位置比例：`relativeCenterY = (viewCenterY - imgRect.top) / imgRect.height`。
    * 利用 CSS 自定义属性 `--global-zoom` 全局无损放大。
    * 缩放完成后，**立刻计算高度差并手动补偿 `container.scrollTop`**，强行把刚才的 `relativeCenterY` 锚点拉回屏幕正中央。
* **体验**：无论用户放大多少倍，眼睛盯着的画面中心点永远纹丝不动，彻底解决了传统 Web 阅读器的“迷路”问题。

### 📊 带热力密度的智能统计系统

**1. 智能防刷的访问计数逻辑 (`backend_logic.py`)**
* **统计逻辑**：在后端的 `update_view_count` 函数中，采用了分层统计策略。分为“目录总点击 (total_views)”和“内部子页面点击 (pages/files)”。
* **防抖与去重**：为了防止用户频繁进退导致数据注水，引入了 `SESSION_TIMEOUT = 60`（60秒防刷机制）。系统会记录 `last_accessed` 时间戳，只有距离上次访问超过 60 秒，主目录的浏览量才会 +1。但对于内部书页（Identifier）的翻页，则会精确记录每一次查阅。

**2. 极高信息密度的“微型直方图” UI (`ui.js` / `style.css`)**
* **展示特色**：在统计列表（Stats View）中，我没有使用臃肿的第三方图表库，而是手写了一个紧凑型直方图 (`compact-histogram`)。
* **渲染逻辑**：
    * 前端 `renderHistogram` 会读取某部作品所有子页面（如漫画的每一页）的访问数据。
    * 找出访问量最高的一页作为基准 `maxItemViews`。
    * 用纯 CSS 动态生成高度条：`height: ${(node.views / maxItemViews) * 100}%`。
* **用户体验**：
    * 用户点开统计条目，下方会立刻展开一排高低起伏的柱状图。哪里柱子高，说明这本漫画/画集的哪一页被反复观看了最多次（精彩名场面）。
    * **一键直达**：鼠标悬停会显示具体页码和次数，点击任何一根柱子（触发 `jumpAndOpen`），系统会瞬间退出统计界面，直接跳转打开对应的图集，并精确滚动定位到那一页！
